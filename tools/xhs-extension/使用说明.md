# 行迹 · 小红书线索采集扩展 — 使用说明

> 状态：**已修复并可加载测试**（提交 `4158889`，已推送到 GitHub）。
> 项目路径：`/Users/weishengqiu/IdeaProjects/whereabouts/tools/xhs-extension/`

## 一、为什么要修

上一轮交付的扩展其实**点了采集必然失败**，有两个真实缺陷：

1. `content.js` 调用 `window.XhsParser.collect()`，但 `manifest.json` 从头到尾没注入 `parser.js` —— 页面里根本没有 `window.XhsParser`。
2. 即使修好注入，扩展是靠"安装时自动注入 content script"工作的；你如果在装扩展**之前**就开着小红书页面，那个页面里没有脚本，点采集还是失败。

这一轮两个都修了，还顺带修了解析器 `stateFallback` 的一个递归 bug（对象节点不下钻，导致从 `__INITIAL_STATE__` 里取不到 `search.feeds` 的笔记）。

## 二、加载扩展（Chrome / Edge）

1. 地址栏输入并回车：
   - Chrome：`chrome://extensions`
   - Edge：`edge://extensions`
2. 右上角打开 **开发者模式**。
3. 点 **加载已解压的扩展程序**。
4. 选择目录：`/Users/weishengqiu/IdeaProjects/whereabouts/tools/xhs-extension/`
5. 工具栏出现图标 **「行迹 · 小红书线索采集」** 即加载成功。

> 加载前可先跑自检：`node tools/xhs-extension/check.mjs`。全部通过就一定能加载；任一失败浏览器加载必然报错。

## 三、采集测试步骤

1. 在同一个浏览器里**登录小红书**（必须登录，未登录页面渲染不出笔记数据）。
2. 打开任一种页面：
   - 搜索结果页：搜"成都旅游"，地址栏形如 `www.xiaohongshu.com/search_result?keyword=...`
   - 笔记详情页：点开任意一篇，地址栏形如 `www.xiaohongshu.com/explore/<id>`
3. 点工具栏的扩展图标 → 点 **「采集当前页」**。
4. 弹窗会列出采到的笔记（标题 / 作者 / 点赞数），状态栏显示"已采集 N 条笔记"。
5. 点 **「复制 JSON」** 或 **「下载 JSON」** 拿到数据。

### 可能出现的提示与处理

| 提示 | 原因 | 处理 |
|---|---|---|
| 请先在浏览器中打开小红书… | 当前标签页不是小红书域名 | 切到小红书页面再点 |
| 未识别到笔记数据 | 未登录 / 页面没加载出笔记 / DOM 改版 | 确认已登录、笔记已显示；若仍失败可能是小红书改版，需更新 `parser.js` 的选择器 |
| 浏览器不允许在扩展/设置页注入 | 在 `chrome://` 页面点的 | 打开真实小红书页面再点 |
| 复制失败 | popup 剪贴板权限受限 | 改用"下载 JSON" |

## 四、把数据导入平台

1. 打开行迹平台 → **口碑数据** 页 → 底部 **「07 / 导入浏览器采集数据」** 卡片。
2. 粘贴刚才复制的 JSON，或上传下载的 `.json` 文件。
3. 确认预览的笔记条数，点 **「导入 N 条线索」**。

**边界**：导入内容只留标题、作者、摘要、链接、点赞数，作为无评分线索保存；**不产生评分、不注入模型提示词、不写入导出的指南**。扩展全程只读你浏览器已渲染的 DOM，不发网络请求、不读 Cookie、不绕过风控。
